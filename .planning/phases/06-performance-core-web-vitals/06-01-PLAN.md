# Phase 6 Plan 1: Performance & Core Web Vitals

## Goal

Keep the public conversion path within the v1.1 resource budget, expose meaningful hero content before JavaScript executes, and prove responsive/reduced-motion interaction on constrained browser profiles without adding a framework, font, image, or performance vendor.

## Existing seams and constraints

- The page is dependency-light and has no image/font bundles; current source resources are approximately 76KB before interaction.
- [site/index.html](/Users/apple/projects/learning-project/ai/agency/site/index.html) currently leaves key hero fields empty for [site/main.js](/Users/apple/projects/learning-project/ai/agency/site/main.js) to populate, so JavaScript-disabled output does not satisfy PERF-02.
- `main.js` must continue to replace fallback strings with the selected Phase 4 variant and retain Phase 5 event/form behavior.
- Existing reduced-motion CSS removes smooth scrolling and transitions; retain that behavior while eliminating any remaining interaction-blocking layout or overflow.
- Performance proof should use local production-like HTTP serving and browser emulation; do not add a production monitoring service or claim field data from a local lab.

## Task 1: Make the critical path HTML-first and stable

**Files:** `site/index.html`, `site/styles.css`, `site/main.js`

1. Populate the hero's initial HTML with the qualified control copy: audience eyebrow, outcome heading, supporting description, 90/10 promise, primary demo action, secondary audit action, and three qualified proof points. Keep the existing `data-*` selectors so Phase 4 variant rendering still overrides them.
2. Ensure title, description, landmarks, both conversion destinations, and the revenue-audit anchor remain usable without JavaScript. Add a concise `<noscript>` notice only where it improves expectation-setting; do not hide the HTML-first hero or claim forms work without the script that owns them.
3. Reserve stable dimensions for the hero proof and persistent action controls so content replacement does not create avoidable layout shift. Preserve the existing responsive breakpoints and prevent horizontal overflow.
4. Audit script loading and CSS ordering for render-blocking or duplicate work. Keep content scripts ordinary and `main.js` deferred; do not introduce a bundler or broad rewrite.
5. Preserve reduced-motion behavior for anchor navigation, dialog/form transitions, FAQ controls, and persistent actions. Ensure primary actions remain visible, focusable, and clickable when motion is reduced.

## Task 2: Add repeatable performance and resilience proof

**Files:** `tests/phase6.test.js`, `tests/phase6.browser.mjs`

1. Add static tests asserting HTML-first hero copy, exactly one meaningful H1, title/description, both conversion destinations, no external font/image dependency, and reduced-motion CSS safeguards.
2. Add browser coverage for:
   - JavaScript-disabled render showing the hero outcome, primary/secondary destinations, title/description, and no blank hero shell.
   - 375px, 768px, and 1440px layouts with no horizontal overflow and no persistent action obstruction.
   - Reduced-motion preference disabling smooth scrolling/nonessential transitions while keeping demo and audit actions usable.
   - A constrained mobile context with primary action activation completing within 200ms after the click dispatch.
3. Capture document/resource transfer bytes before interaction and assert the 500KB pre-interaction budget. Record navigation timing and `PerformanceObserver` LCP/CLS where supported; assert LCP ≤ 2.5s, CLS ≤ 0.1, and document the limitation when local headless Chromium cannot expose INP reliably.
4. Keep the proof deterministic and local. Use the existing Playwright dependency and owned HTTP server; do not send telemetry or require an HTTPS vendor endpoint.
