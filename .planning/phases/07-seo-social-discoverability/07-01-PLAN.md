# Phase 7 Plan 1: SEO & Social Discoverability

## Goal

Make the public page intentional for search and social consumers without inventing a domain, exposing internal artifacts, or turning illustrative business claims into unsupported structured data.

## Release gate

Confirmed public HTTPS origin: `https://agenticera.in/`. Use this exact normalized URL for canonical, `og:url`, sitemap, and robots references. Do not add localhost, placeholder, or endpoint URLs.

## Existing seams and constraints

- [site/index.html](/Users/apple/projects/learning-project/ai/agency/site/index.html) already has language, viewport, title, description, one H1, skip link, header/nav/main/footer landmarks, and HTML-first hero copy.
- The site is a static directory; robots and sitemap files belong directly under `site/`.
- The existing Apps Script endpoint is an operational form destination, not a public page and must never appear in SEO/social metadata, sitemap, robots comments, or structured data.
- No ratings, testimonials, guaranteed savings, fabricated reviews, or unverified organization facts may be added.
- A real branded SVG social card is acceptable; it must contain coherent title/description guidance, fixed dimensions, and no placeholder asset path.
- Do not add analytics, CRM, portal, or framework infrastructure.

## Task 1: Establish public metadata and social asset after URL confirmation

**Files:** `site/index.html`, `site/social-card.svg`

1. Confirm the exact HTTPS public URL at the release gate and normalize it with a trailing slash.
2. Add one canonical link and complete Open Graph/Twitter-compatible metadata using the approved title, description, canonical URL, `og:type=website`, and the real social-card asset URL.
3. Keep metadata aligned with the super-intelligent AI departments proposition; do not introduce new savings, case-study, review, or guarantee claims.
4. Create a branded SVG social card with explicit `1200x630` dimensions, readable brand/title treatment, and safe contrast. Add image `alt` guidance in metadata/documentation without exposing internal file paths.
5. Verify the raw source still contains exactly one meaningful H1, valid language/viewport metadata, crawlable landmarks, and the HTML-first conversion destinations.

## Task 2: Make crawling intentional and structured data conservative

**Files:** `site/robots.txt`, `site/sitemap.xml`, `site/index.html`

1. Add `robots.txt` allowing the public page and naming only the confirmed public sitemap URL. Do not mention `.planning`, tests, secrets, or debug paths as discoverable links.
2. Add a one-URL sitemap for the confirmed public origin with a valid XML namespace and no internal artifact URLs.
3. Decide structured data by evidence: omit JSON-LD if only unverified business facts are available; otherwise add only verifiable Organization/Service fields already present in the page. Never add ratings, reviews, testimonials, financial guarantees, or fabricated aggregate scores.
4. Ensure no public metadata, visible link, sitemap entry, or robots directive contains the Apps Script endpoint, test paths, `.planning`, or debug/event identifiers.

## Task 3: Add source and browser verification

**Files:** `tests/phase7.test.js`, `tests/phase7.browser.mjs`

1. Add static tests for title/description/canonical, exact H1 count, language/viewport, Open Graph fields, absolute confirmed URLs, SVG dimensions, robots/sitemap syntax, and absence of internal/endpoint paths.
2. Add browser/source coverage with JavaScript disabled to verify metadata and landmarks remain available without runtime rendering.
3. Parse sitemap XML and assert it contains only the confirmed canonical URL. Validate JSON-LD only if the implementation includes it.
4. Run all prior contract tests, Phase 6 browser proof, Phase 7 tests, JavaScript checks, and `git diff --check`.
