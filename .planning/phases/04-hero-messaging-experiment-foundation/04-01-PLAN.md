## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser configuration -> variant resolver | Configuration and storage values are untrusted and must not select unapproved copy or identifiers. |
| Browser interaction -> local event seam | CTA and exposure payloads cross from user-controlled DOM state into future instrumentation; direct contact fields must not cross this seam. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-01 | Tampering | `PHASE4_CONTENT` variant resolver | medium | mitigate | Validate experiment enabled state and variant IDs against the versioned allowlist; resolve malformed storage/configuration to control/no-test. |
| T-04-02 | Information Disclosure | `main.js` hero/CTA event seam | high | mitigate | Construct payloads from journey, placement, page context, and approved variant metadata only; explicitly exclude names, phone numbers, emails, free text, and full form values. |
| T-04-03 | Repudiation | exposure guard in `main.js` | medium | mitigate | Persist one experiment/variant exposure marker in session scope and test repeated initialization and interaction. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | Permit only the pinned `playwright@1.56.1` dev dependency and Chromium install required for Phase 4 browser verification; reject all other new packages and keep runtime site dependencies at zero. |
</threat_model>
