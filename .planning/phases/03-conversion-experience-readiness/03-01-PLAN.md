## Trust Boundaries

| Boundary | Description |
|---|---|
| Visitor input → browser DOM/state | Untrusted names, company text, phone values, and bottleneck text enter client-side form state and status rendering. |
| Browser → conversion UI | Visitors can trigger modal, audit, FAQ, navigation, and persistent-action state transitions from mouse, touch, keyboard, or assistive technology. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-01 | Tampering | Demo and audit form state | medium | mitigate | Use native constraints plus explicit client-side validation, render feedback through controlled text/status nodes, and keep submission local-only with no external transport. |
| T-03-02 | Information Disclosure | Conversion form copy/status | medium | mitigate | Collect only requested fields, show the privacy/minimal-collection note beside each path, avoid echoing sensitive phone values in success messages, and do not persist data. |
| T-03-03 | Denial of Service | Modal, accordion, and persistent controls | low | mitigate | Use bounded DOM state, idempotent open/close handlers, Escape/backdrop recovery, and reduced-motion-safe transitions so repeated input cannot leave the page unusable. |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager installs are planned; retain dependency-free browser-native implementation and reject new runtime dependencies. |
</threat_model>
