# Phase 5 Plan 1: Conversion UX & Privacy-Safe Measurement

## Goal

Make the existing demo and revenue-audit journeys complete, understandable, duplicate-safe, and locally verifiable while preserving the configured Google Sheets capture behavior and the explicit v1.1 boundary against production analytics, calling, messaging, calendar, CRM, or portal workflows.

## Existing seams and constraints

- Both journeys already share native labels, required controls, `role="status"` live regions, consent checkboxes, and `submitLead()` in [site/index.html](/Users/apple/projects/learning-project/ai/agency/site/index.html) and [site/main.js](/Users/apple/projects/learning-project/ai/agency/site/main.js).
- Phase 4 provides `variantContext`, `emit()`, session-safe exposure, and privacy-safe event storage in `window.__PHASE4_EVENTS`; extend this seam instead of adding a second analytics abstraction.
- `submitLead()` must remain a no-op when `LEAD_CAPTURE_CONFIG.endpoint` is absent and must continue to be the only configured external lead transport.
- Contact fields may be sent only to the existing lead-capture endpoint; event payloads must never include name, company, phone, WhatsApp, email, bottleneck, consent text, or complete form values.
- Existing simulated/local success copy and configured Google Sheets success copy must remain distinct and must state the actual human follow-up or retry path.

## Task 1: Define the conversion contract and shared form state

**Files:** `site/content/phase3.js`, `site/main.js`, `site/index.html`

1. Add implementation-facing event contract metadata for versioned events:
   - `page_view`
   - `cta_click`
   - `form_start`
   - `validation_failure`
   - `form_submit_attempt`
   - `form_outcome`
   Each event must document trigger and allowed non-personal fields.
2. Extend the existing `emit()` payload with stable `journey`, `placement`, `section`, device class, selected industry, currency, and active experiment context where available. Normalize values through allowlists/defaults; never pass raw input values.
3. Emit one `page_view` after initialization and emit `form_start` once per journey when a visitor first focuses or edits a form.
4. Add field-level error targets and `aria-describedby`/`aria-invalid` wiring for both forms. Preserve entered values on validation failure and announce the first actionable error in the existing live region.
5. Add shared in-flight/submission state and an idempotency key per form state so rapid repeated submits cannot issue multiple lead captures or duplicate attempt/outcome records. Re-enable controls only after the request settles or the user changes the invalid state as appropriate.
6. Emit `validation_failure` for required, consent, and phone failures without including field values; emit `form_submit_attempt` only after validation passes.

## Task 2: Complete outcome handling and expectation-setting

**Files:** `site/main.js`, `site/content/phase3.js`, `site/styles.css`

1. Add a single success/failure outcome path for both journeys that emits `form_outcome` with `outcome` (`captured`, `simulated`, or `retry`) and preserves journey/context fields.
2. Ensure configured endpoint success says the enquiry was recorded and a human will contact the visitor; simulated/no-endpoint success says no real call or external submission occurred and gives the next human follow-up expectation.
3. Ensure network or endpoint failure gives a retry instruction, leaves entered values available where useful, and does not present a success-shaped fallback.
4. Keep audit and demo actions reachable from the hero, ROI/pricing area, and persistent action bar. Add only the smallest missing CTA anchor or explicit `data-` placement marker needed for event attribution.
5. Make duplicate prevention and disabled-submit states visibly understandable and keyboard-safe, including focus remaining on the status/error or returning to the first invalid field.
6. Preserve reduced-motion behavior and prevent the persistent bar from covering focused form controls at 375px, 768px, and 1440px.

## Task 3: Add local contract and browser proof

**Files:** `tests/phase5.test.js`, `tests/phase5.browser.mjs`, `package.json`

1. Add static/runtime tests asserting the event contract names, required payload allowlist, privacy exclusions, no-op behavior with absent analytics sink, duplicate guard, field error relationships, and honest success/failure copy.
2. Add Playwright coverage at 375px, 768px, and 1440px for:
   - hero, ROI/pricing, and persistent CTA reachability;
   - keyboard completion and inline error recovery for both forms;
   - accessible status announcements;
   - rapid-submit deduplication;
   - local event ordering for both journeys;
   - event payload absence of contact/free-text fields;
   - blocked/absent analytics sink leaving the form usable.
3. Run existing Phase 3/4 tests alongside Phase 5 tests, JavaScript syntax checks, browser proof, and `git diff --check`.
4. Document the event contract in the implementation-facing test/source contract rather than creating a production analytics destination.
